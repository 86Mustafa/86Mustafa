# نظام مبيعات أدوية شركة دجلة / الديوانية

تطبيق ويب لإدارة الأدوية والطلبات والمخزون والتقارير لمندوب مبيعات شركة دجلة للصناعات الدوائية.

## هيكل المشروع

```
dijla-app/
├── public/                 # الواجهة (يقدّمها الخادم؛ لا يُقدَّم أي ملف خارج هذا المجلد)
│   ├── index.html
│   └── images/dijla.png
└── backend/
    ├── src/
    │   ├── server.js       # نقطة التشغيل
    │   ├── app.js          # إعداد Express والأمان والمسارات
    │   ├── db.js           # قاعدة بيانات SQLite والترحيلات
    │   ├── auth.js         # تسجيل الدخول والجلسات
    │   ├── permissions.js  # الأدوار والصلاحيات
    │   ├── validation.js   # التحقق من المدخلات
    │   ├── images.js       # رفع صور الأدوية
    │   ├── routes/         # auth, products, orders, users, backup
    │   └── cli/create-user.js
    ├── test/api.test.js
    ├── .env.example
    └── data/               # يُنشأ تلقائياً: قاعدة البيانات والصور (لا يُرفع إلى Git)
```

## التشغيل

يتطلب **Node.js 20 أو أحدث**.

```bash
cd dijla-app/backend
npm install
npm start
```

ثم افتح `http://localhost:3001`. تُطبع في نافذة الخادم أيضاً عناوين الشبكة المحلية (مثل `http://192.168.1.5:3001`) لفتح التطبيق من الهاتف أو جهاز آخر على نفس الشبكة.

### أول تشغيل
- يُنشأ حساب مدير باسم `admin`، و**تُطبع كلمة المرور المؤقتة في نافذة الخادم**. احفظها، فسيُطلب تغييرها عند أول دخول.
- لتحديد كلمة المرور بنفسك: انسخ `.env.example` إلى `.env` وضع `ADMIN_PASSWORD` قبل أول تشغيل.

### نقل البيانات من النسخة السابقة
كانت النسخة السابقة تحفظ البيانات داخل المتصفح. توجد طريقتان لنقلها:
1. **تلقائياً**: افتح التطبيق الجديد **من نفس المتصفح ونفس العنوان** الذي كنت تستخدمه، وسجّل الدخول كمدير. إذا كان الخادم فارغاً سيُعرض عليك نقل البيانات.
2. **يدوياً**: من النسخة القديمة اضغط «نسخ احتياطي»، ثم في النسخة الجديدة اضغط «استعادة بيانات» واختر الملف.

### الأدوار
| الدور | الصلاحيات |
|---|---|
| مندوب / كاشير | عرض الأدوية والمخزون، إنشاء الطلبات والفواتير |
| مشرف | ما سبق + إضافة وتعديل الأدوية، تجهيز واسترجاع وحذف الطلبات، التقارير |
| مدير النظام | كل الصلاحيات + حذف الأدوية، النسخ الاحتياطي والاستعادة، إدارة المستخدمين |

يُضاف المستخدمون من صفحة «المستخدمون». الصلاحيات تُفرض على الخادم، وإخفاء الأزرار في الواجهة للتنظيم فقط.

### نسيت كلمة مرور المدير؟
```bash
cd dijla-app/backend
npm run create-user -- admin admin
```
تُطبع كلمة مرور مؤقتة جديدة.

### التشغيل الدائم (PM2)
```bash
npm i -g pm2
cd dijla-app/backend
pm2 start src/server.js --name dijla
pm2 save
pm2 logs dijla
```

### النسخ الاحتياطي
- زر «نسخ احتياطي» يحفظ ملف JSON يحتوي كل الأدوية (مع صورها) والطلبات.
- أو انسخ مجلد `backend/data` كاملاً، لكن بعد إيقاف الخادم.

### الاختبارات
```bash
cd dijla-app/backend
npm test
```

## سجل التغييرات

### المرحلة الأولى: إصلاحات وأمان
- **إصلاح تكرار أزرار الطلبات**: كان زر «عرض» يفتح الفاتورة أكثر من مرة، وقد يتكرر تأكيد الحذف، لأن كل جدول كان يربط مستمعاً على أزرار الجداول الأخرى. صار هناك مستمع واحد مفوَّض (event delegation).
- **سد ثغرة XSS**: كل النصوص المعروضة (أسماء الأدوية والصيدليات والملاحظات...) تمر عبر `escapeHtml`، بما في ذلك الفواتير والتقارير المطبوعة. وتُوحَّد السجلات عند التحميل والاستعادة (الأرقام أرقام والنصوص نصوص)، ويُرفض ملف النسخة الاحتياطية غير الصالح.
- **توحيد حد المخزون المنخفض**: ثابت واحد `LOW_STOCK_THRESHOLD = 10` (و`CRITICAL_STOCK_THRESHOLD = 5` لحالة «منخفض جداً») في لوحة التحكم والتنبيه والتقارير.
- **تاريخ نهاية التقرير**: كان الحقل يحتوي نص `${new Date()...}` حرفياً، وأصبح يُضبط على تاريخ اليوم عند فتح التطبيق.
- **التواريخ بالتوقيت المحلي**: كان `toISOString()` يسجّل تاريخ الأمس للطلبات المنشأة بين منتصف الليل والساعة 3 فجراً بتوقيت العراق.
- **مسار الشعار**: `images\dijla.png` أصبح `images/dijla.png` ليعمل على كل الخوادم.
- **الصور الافتراضية**: خدمة `via.placeholder.com` متوقفة، فاستُبدلت بصورة SVG محلية تعمل بدون إنترنت، وتُستبدل الروابط القديمة المخزنة تلقائياً.
- **تصدير Excel**: يعمل الآن (ملف `.xlsx` متعدد الأوراق باتجاه من اليمين لليسار، حسب الخيارات المحددة والفترة)، مع بديل CSV عند عدم توفر الإنترنت.
- **تنظيف المشروع**: حُذفت الملفات المؤقتة والمكررة والفارغة، وأُعيدت تسمية `Untitled-1.html` إلى `index.html`.

### المرحلة الثانية: خادم موحّد وتسجيل دخول
- **خادم واحد** (Express + SQLite عبر `better-sqlite3`) بدل ثلاثة خوادم غير مكتملة، مع ترحيلات لقاعدة البيانات.
- **الواجهة تعمل عبر الـ API**: البيانات على الخادم وتُشارَك بين كل الأجهزة. السلة فقط تبقى في المتصفح.
- **تسجيل الدخول**: كلمات المرور مشفّرة بـ bcrypt، والجلسة في ملف تعريف `httpOnly` و`SameSite=Strict`، مع حد لمحاولات الدخول (10 كل 15 دقيقة). يجب تغيير كلمة المرور المؤقتة عند أول دخول. تغيير كلمة المرور أو الدور أو تعطيل المستخدم يُنهي جلساته فوراً.
- **أدوار وصلاحيات تُفرض على الخادم**، وصفحة لإدارة المستخدمين.
- **الخادم يحسب الأسعار والإجماليات** من قاعدة البيانات، ويتجاهل أي سعر يرسله المتصفح.
- **معاملات (transactions)**: تجهيز الطلب يخصم المخزون ويغيّر الحالة معاً أو لا شيء. لا يمكن تجهيز طلب مرتين، ولا استرجاع طلب غير مكتمل، ولا حذف طلب مكتمل.
- **حالات الطلب موحّدة** (`pending` / `completed` / `returned`) وتُعرض بالعربية في الواجهة.
- **الصور تُرفع كملفات** بعد التحقق من نوعها الفعلي، وتُعرض للمستخدمين المسجلين فقط.
- **الخادم يقدّم مجلد `public` فقط**، مع ترويسات أمان (CSP وغيرها) ورسائل خطأ لا تكشف تفاصيل داخلية.
- **الاستعادة تقبل نسخ الإصدار السابق**: تحوّل الحالات العربية والتواريخ بالأرقام العربية والصور المضمّنة، وتعرض نقل بيانات المتصفح القديمة تلقائياً.
- **تاريخ الطلب بتوقيت بغداد** على الخادم، بغض النظر عن توقيت الجهاز.
- **إصلاح عرض الهاتف**: كانت الصفحة أعرض من الشاشة، فتظهر شاشة الدخول مزاحة.
- 23 اختباراً آلياً للـ API.

## الخطوات القادمة (المرحلة الثالثة)
- **قائمة تنقّل للهاتف**: القائمة الجانبية مخفية على الشاشات الصغيرة منذ النسخة الأصلية، فلا يمكن التنقل بين الصفحات من الهاتف.
- تحويل التطبيق إلى PWA يعمل دون اتصال.
- تاريخ انتهاء الصلاحية ورقم الدفعة لكل دواء.
- سجل الصيدليات والذمم.
- فصل JavaScript وCSS إلى ملفات مستقلة لتشديد سياسة CSP (إزالة `unsafe-inline`).
- تشغيل التطبيق عبر HTTPS عند نشره خارج الشبكة المحلية (`COOKIE_SECURE=true`).
